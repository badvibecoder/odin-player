# odin-player

A minimal, terminal-driven music/audiobook player written in [Odin](https://odin-lang.org).
It uses only Odin `core` libraries and the bundled [`vendor:miniaudio`](https://miniaud.io)
for audio.

Two-pane interface: a **now-playing pane** on top and a **file-browser navigation pane**
below. Navigation is locked to the directory you open (it can't crawl the rest of the
filesystem) and only shows folders plus `.mp3` / `.wav` files.

```
┌────────────────────────────────────────────────────────┐
│ odin-player                                             │
│   ▶ Asphalt at Daybreak    ← marquee (scrolls)          │
│   [Playing]  Vol 100%  Shuffle:off  Loop:All  Autosave:on│
│   [██████··················] 1:24 / 3:00                │
│ /home/me/music                                           │
│    ..                                                    │
│  > rock/                                                 │
│    ambient/                                              │
│    song.mp3                                              │
│                                                          │
│  ↑/↓ Move   ← Up   →/Enter Open   Space Play/Pause  ...  │
│  a/d Seek   n/b Prev/Next   r Shuffle   l Loop  ...      │
└────────────────────────────────────────────────────────┘
```

## Features

- Recursive-safe, **root-locked** folder browsing (never goes above the directory you opened).
- Shows **only audio files** (`.mp3`, `.wav`); folders are listed, everything else is hidden.
- **Scrolling marquee** for the now-playing track name (old MP3-player style).
- **Seek** with hold-to-accelerate (tap = 10s, hold = ramps up).
- **Loop modes** (All / One / Off) and **shuffle**.
- **Resume**: reopens the last track at the last playback position.
- **Auto-save**: progress is saved to disk every 30 seconds, so a crash or power loss
  costs at most ~30 seconds of listening — useful for audiobooks and lectures.
- **4 ANSI color schemes**, terminal-resize handling (SIGWINCH), and clean shutdown.
- Config persisted to `~/.odin-player/config.json`.

## Requirements

- **Linux** with a terminal (uses termios + ioctl).
- An audio output device (ALSA / PulseAudio / PipeWire, etc. — miniaudio auto-detects).
- **To build:** [Odin](https://odin-lang.org/docs/install/) (tested with `dev-2026-08`),
  a C compiler (`cc`/`gcc`/`clang`), and `ar` (binutils).

## Installation

### Option A — Prebuilt binary (release)

Download the `odin-player` binary for your platform, make it executable, and run it:

```sh
chmod +x odin-player
./odin-player /path/to/music
```

It's a single self-contained executable (statically links miniaudio; dynamically links
only the system `libc` and `libm`).

### Option B — Build from source

The audio library (`vendor/miniaudio`) needs two things: the Odin bindings and a compiled
`lib/miniaudio.a`. The bindings ship in this repo; the static library is compiled from the
miniaudio sources in your Odin install.

```sh
# 1. Install Odin and a C toolchain (cc + ar).

# 2. (Optional) Refresh the miniaudio Odin bindings from your Odin install:
ODIN_ROOT="$(odin root)"
mkdir -p vendor/miniaudio/lib
cp "$ODIN_ROOT/vendor/miniaudio/"*.odin vendor/miniaudio/

# 3. Compile the miniaudio C library:
cc -c -O2 -fPIC "$ODIN_ROOT/vendor/miniaudio/src/miniaudio.c" -o /tmp/miniaudio.o
ar rcs vendor/miniaudio/lib/miniaudio.a /tmp/miniaudio.o
rm -f /tmp/miniaudio.o

# 4. Build the player:
./build.sh
```

The result is the `odin-player` executable in the project root.

> **Why the extra steps?** The system `vendor` collection is read-only and ships miniaudio
> *without* a prebuilt `lib/miniaudio.a` on Linux. This project keeps a local copy of the
> package and points the compiler at it through a project-local `ODIN_ROOT`
> (`odinhome/`, regenerated by `build.sh`). The bindings and the compiled library must
> come from the **same** Odin install so their versions match.

## Usage

```sh
./odin-player                 # reopen the last directory (from config.json)
./odin-player /path/to/music  # open a specific directory
```

Browse into folders, select a file, and press **Enter** to play it. Press **q** to quit.

A few test MP3s are included in [`testmusic/`](testmusic/):

```sh
./odin-player testmusic
```

## Controls

**Navigation pane**

| Key | Action |
|---|---|
| `↑` / `↓` | Move selection |
| `→` or `Enter` | Open folder / play file |
| `←` | Go up to the parent folder |
| `..` entry | Also goes up to the parent (only shown inside subfolders) |

**Playback**

| Key | Action |
|---|---|
| `Space` | Play / pause |
| `w` / `s` | Volume up / down |
| `a` / `d` | Seek backward / forward (tap = 10s, hold = ramp up to 60s) |
| `n` / `b` | Next / previous track (within the current folder) |
| `r` | Toggle shuffle |
| `l` | Cycle loop mode: **All → One → Off** |
| `p` | Toggle periodic auto-save |
| `c` | Cycle color scheme |
| `q` | Quit (saves config + restores the terminal) |

## How playback works

- Playing a file makes its **folder** the playback context: auto-advance, `n`/`b`, shuffle,
  and loop all operate on the audio files in that folder (each folder acts like an album).
- **Loop Off** stops after the last track in the folder; **Loop All** wraps around;
  **Loop One** repeats the current track.
- Browsing to another folder does *not* interrupt what's playing — only selecting a file does.

## Configuration

Settings live in `~/.odin-player/config.json` and are written automatically on quit and
every 30 seconds (when auto-save is on).

```json
{
  "directory":    "/home/me/music",
  "volume":       0.9,
  "color_scheme": 1,
  "loop":         0,
  "random":       false,
  "track_path":   "/home/me/music/chapter12.mp3",
  "position":     1234.5,
  "autosave":     true
}
```

| Field | Type | Meaning |
|---|---|---|
| `directory` | string | Last opened (root) directory |
| `volume` | float | 0.0 – 1.0 |
| `color_scheme` | int | 0 – 3 |
| `loop` | int | `0` = All, `1` = One, `2` = Off |
| `random` | bool | Shuffle on/off |
| `track_path` | string | Last playing file (used for resume) |
| `position` | float | Playback position in seconds (used for resume) |
| `autosave` | bool | Periodic 30-second progress saving |

You can delete this file at any time to reset all settings.

## Tuning (optional)

A few behaviors are one-line constants at the top of [`main.odin`](main.odin):

| Constant | Default | What it controls |
|---|---|---|
| `MARQUEE_SPEED` | `250 * time.Millisecond` | Marquee scroll speed |
| `MARQUEE_WIDTH` | `36` | Marquee display width |
| `MARQUEE_PAD` | `4` | Spaces after the title before it loops |
| `SEEK_BASE` | `10.0` | Seconds per seek tap |
| `SEEK_MAX_LEVEL` | `6` | Max ramp (→ 60s per repeat) |
| `AUTOSAVE_INTERVAL` | `30 * time.Second` | How often progress is saved |

## Notes

- The terminal is switched to raw/non-blocking mode while running and restored on exit
  (including on `q`).
- If the saved resume file no longer exists (or is outside the directory you opened),
  the player starts stopped instead of erroring.

## Development with DeepSeek v4 Pro

This project was built end-to-end with **DeepSeek v4 Pro** (provider
`deepseek-official`) through the DeepSeek Harness, using an iterative,
test-driven workflow: each feature was implemented, built, and verified against
the terminal (via PTY-based tests) before moving on — audio skeleton → directory
scanning → TUI/progress/resize → state/loop/persistence → the two-pane
navigation redesign, marquee, and seek.

**Model(s) used**

- `deepseek-v4-pro` — the primary coding model (~254 responses).
- `deepseek-v4-flash` — 2 small helper calls.
- `session-title-first-prompt-llm` — 1 call (names the session), negligible.

**Token usage by type** (snapshot at end of development)

| Type | Tokens |
|---|---|
| Fresh input (prompt) | 131,717 |
| Cached input (context re-read) | 52,314,880 |
| Output (completion) | 330,103 |
| Reasoning (thinking) | 239,814 |
| **Grand total** | **52,776,700** |

**Efficiency**

- **~99.7% of input was served from cache.** The harness re-reads the
  conversation context (52.3M cached vs ~132K fresh), so each iterative turn
  paid mostly for the *new* delta rather than re-sending the whole history —
  that's what made the long phase-by-phase build practical.
- **~73% of output was reasoning/thinking** (240K), with the remaining ~90K
  tokens being the visible code, commands, and prose.
- Bug fixes (the raw-mode `\r\n` issue, audio underruns, and two memory bugs)
  were each found and fixed within a single follow-up turn thanks to
  reproducing behavior through the terminal and reading exact byte-level output.
